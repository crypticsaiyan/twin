twin needs **Node 22 or newer**. It runs straight from the repository with `npx`; there is nothing to install globally.

<Tabs>
<TabItem label="Reporter">

You have a command that fails on your machine. Nothing is uploaded and no account is needed.

<Steps>

1. In the project where the command fails, run it through twin:

   ```sh
   npx @crypticsaiyan/twincli capture -- npm test
   ```

   Put your own failing command after `--`. twin runs it as usual; you see its output live.

2. twin prints a summary of what it recorded (command, system, toolchain, repository, environment, redaction) and asks:

   ```text
   Write twin-capsule.json? [y]es / [n]o / [v]iew full JSON:
   ```

   Press `v` to read the full JSON first, `y` to write it, `n` to abort.

3. Attach `twin-capsule.json` to the issue. On GitHub, drag the file into the comment box.

</Steps>

<Aside type="caution">
Redaction is pattern based. Environment variable values are not recorded except for a short allowlist, but read the capsule before posting it publicly. See [Privacy](../../reference/privacy/).
</Aside>

</TabItem>
<TabItem label="Maintainer">

You have a capsule from an issue and want to see the failure.

<Steps>

1. Get a Solari API key from [console.getsolari.com](https://console.getsolari.com). Export it, or put it in a `.env` file in the project; twin reads `SOLARI_API_KEY` from the nearest `.env` above the working directory that sets it.

   ```sh
   export SOLARI_API_KEY=slr_live_...
   # or
   echo 'SOLARI_API_KEY=slr_live_...' >> .env
   ```

2. Replay the capsule. Pass the attachment link from the issue directly, or a downloaded file:

   ```sh
   npx @crypticsaiyan/twincli replay https://github.com/user-attachments/files/<id>/twin-capsule.json
   npx @crypticsaiyan/twincli replay twin-capsule.json
   ```

   twin creates a fresh Linux sandbox, installs the captured Node version, fetches the exact commit, applies the reporter's uncommitted diff, installs the captured package manager and dependencies from the lockfile, sets the captured environment values and time zone, and runs the command three times.

3. Read the verdict. `REPRODUCED` means every attempt failed exactly as on the reporter's machine. The other verdicts are explained in [Replay](../../guides/replay/).

4. Keep going:

   ```sh
   npx @crypticsaiyan/twincli replay twin-capsule.json --keep      # leave it running at the failure
   npx @crypticsaiyan/twincli shell                                # open a terminal on it (Ctrl-] detaches)
   npx @crypticsaiyan/twincli bisect twin-capsule.json --good mine.json
   npx @crypticsaiyan/twincli verify twin-capsule.json --patch fix.patch
   npx @crypticsaiyan/twincli stop                                   # release anything still running
   ```

</Steps>

A good capsule for `bisect` is one you capture yourself where the command passes: `twin capture -- npm test` on your machine, at the same commit.

</TabItem>
</Tabs>

## Try it on a real issue

The repository ships the capsules from [apache/echarts#21538](../../examples/echarts-21538/). With a key set, from a clone:

```sh
twin replay examples/echarts-21538/new-york.json
twin bisect examples/echarts-21538/new-york.json --good examples/echarts-21538/kolkata.json
twin verify examples/echarts-21538/new-york.json --patch examples/echarts-21538/fix.patch
```

Each takes about 70 seconds on Solari.

## Working from a clone

```sh
git clone https://github.com/crypticsaiyan/twin
cd twin
pnpm install
pnpm dev replay examples/echarts-21538/new-york.json   # run from source (Node 22.18+)
pnpm build && node dist/bin.js --help                  # or compile first
```
